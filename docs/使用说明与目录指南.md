# Python A2A Runtime 使用说明与目录指南

状态：V1 Release Candidate — `0.1.0rc5`

这个 Runtime 可以开始试用了。它是一个本地 Markdown File-based A2A v1.0.0 运行时，用来管理任务、状态、消息、审核、阻塞、风险、Prompt 和最终交付。它不会自动修改业务源码，不会调用真实 LLM，也不会自动执行 Cursor Prompt。

## 一句话理解

Runtime 负责“流程、文件、门禁、验收”；Cursor 或人工负责“真正理解需求并写业务代码”。

## 顶层目录说明

| 目录 / 文件 | 作用 | 使用建议 |
|---|---|---|
| `a2a_runtime/` | Python Runtime 源码。包含 CLI、模型、仓储、服务、状态机和 Agent 骨架。 | 日常使用不需要直接改这里；后续开发 Runtime 才修改。 |
| `a2a_runtime/cli.py` | CLI 入口。支持 `python3.11 -m a2a_runtime.cli ...`。 | 推荐通过这个入口使用 Runtime。 |
| `a2a_runtime/commands/` | CLI 命令实现，例如 `status`、`task`、`prompt`、`gate`、`risk`、`review`、`blocker`、`finalize`、`report`。 | 新增 CLI 命令时放这里。 |
| `a2a_runtime/core/` | 核心基础设施：路径、ID、frontmatter、常量、错误、时间。 | 保持稳定，避免随意改动协议相关常量。 |
| `a2a_runtime/models/` | dataclass + Enum 模型，如 Task、State、Message、Artifact、Blocker、Review、Risk。 | 修改模型前要确认不破坏 Markdown A2A v1.0.0 兼容性。 |
| `a2a_runtime/repositories/` | 文件仓储层，负责读写 workspace 中的 Markdown 文件。 | CLI 不应绕过 repository/service 直接写运行时文件。 |
| `a2a_runtime/services/` | 业务服务层：状态机、Gate、Blocker、Review、Risk、Final Delivery、Prompt、Report。 | 运行时规则主要在这里。 |
| `a2a_runtime/agents/` | Agent 骨架与 FlowControllerAgent 门面。 | 当前不调用真实 LLM，只提供流程封装。 |
| `a2a_runtime/profiles/` | 默认 Agent Profile / persona 片段。 | 用于 PromptService 融合生成提示词。 |
| `tests/` | unittest 测试，包括单元测试、CLI 测试、E2E sandbox 测试、release metadata 测试。 | 修改 Runtime 后必须跑全量测试。 |
| `docs/` | 使用、发布、验收、安全边界等文档。 | 当前这份说明也在这里。 |
| `README.md` | 总览、Quick Start、Safety Model、Release Checklist。 | 新用户先读 README，再读本文件。 |
| `CHANGELOG.md` | 版本变更记录。 | 发布前更新。 |
| `pyproject.toml` | 包元数据和 entry point。 | 当前版本号为 `0.1.0rc5`。 |
| `.ai-agents/` | A2A 协议、Agent cards、flows、handoffs、rules、templates、workspace。 | Runtime 可以读协议文件；不要修改协议结构。 |
| `.ai-agents/workspace/` | 真实任务 workspace。每个任务一个 `T-YYYY-NNN` 目录。 | CLI 的写入主要发生在这里。真实项目使用前先确认 `--project-root`。 |
| `.cursor/` | Cursor 规则或计划目录。 | Runtime 不修改 `.cursor/**`。 |
| `归档/` | 同事 persona / 参考资料来源。 | AgentProfileService 可读取，不作为 Runtime 写入目标。 |

## `.ai-agents/workspace/<task-id>/` 目录说明

每个任务目录名必须等于 `task_id`，例如：

```txt
.ai-agents/workspace/T-2026-001/
```

| 路径 | 作用 | 谁写 |
|---|---|---|
| `task.md` | 静态任务字段，例如标题、类型、优先级、owner。 | `task create` / TaskService |
| `state.md` | 唯一动态状态源，例如 current_status、current_agent、review 状态、active blocker。 | Controller 流程 / StateRepo |
| `messages/**` | 文件消息总线，保存 handoff、review、blocker、risk decision 等消息。 | 各 Service 受控写入 |
| `artifacts/pm/**` | PM 产物，例如 requirement、prd、task-breakdown。 | PM / Cursor 生成，Runtime 不伪造 |
| `artifacts/architect/**` | Architect 产物，例如 tech-plan、file-change-plan、risk-plan。 | Architect / Cursor 生成 |
| `artifacts/developer/**` | Developer 产物，例如 implementation-log、changed-files。 | Developer / Cursor 生成 |
| `artifacts/qa/**` | QA 产物，例如 test-report、acceptance-checklist。 | QA / Cursor 生成 |
| `artifacts/final/**` | Final Delivery。 | `finalize` / FinalDeliveryService |
| `human-reviews/**` | Human Review 记录，例如 architect-review、final-review。 | `review approve/reject` 代理用户写入 |
| `blockers/**` | Formal Blocker 记录。 | Controller 通过 BlockerService 创建 |
| `archive/**` | 报告导出、后续归档文件。 | `report --output archive/...` |

## 快速开始

先确认 CLI 可用：

```bash
python3.11 -m a2a_runtime.cli --help
```

创建任务：

```bash
python3.11 -m a2a_runtime.cli --project-root . task create \
  --type feature \
  --title "新增设置页" \
  --priority P1 \
  --owner zhangxia \
  --yes
```

查看状态：

```bash
python3.11 -m a2a_runtime.cli --project-root . status
```

生成 PM Prompt：

```bash
python3.11 -m a2a_runtime.cli --project-root . prompt pm
```

生成 Architect Prompt：

```bash
python3.11 -m a2a_runtime.cli --project-root . prompt architect
```

Architect 方案人工审核通过后：

```bash
python3.11 -m a2a_runtime.cli --project-root . review approve \
  --stage architect \
  --reviewer zhangxia \
  --yes
```

生成 Developer Prompt：

```bash
python3.11 -m a2a_runtime.cli --project-root . prompt developer \
  --path src/pages/settings/index.tsx \
  --operation modify
```

Developer Gate dry-run：

```bash
python3.11 -m a2a_runtime.cli --project-root . gate developer \
  --path src/pages/settings/index.tsx \
  --operation modify
```

查看报告：

```bash
python3.11 -m a2a_runtime.cli --project-root . report
```

导出报告到当前任务 archive：

```bash
python3.11 -m a2a_runtime.cli --project-root . report \
  --output archive/runtime-report.md \
  --yes
```

## 常用命令速查

### 只读命令

这些命令默认不写文件：

```bash
python3.11 -m a2a_runtime.cli --project-root . status
python3.11 -m a2a_runtime.cli --project-root . validate
python3.11 -m a2a_runtime.cli --project-root . task list
python3.11 -m a2a_runtime.cli --project-root . task active
python3.11 -m a2a_runtime.cli --project-root . prompt controller
python3.11 -m a2a_runtime.cli --project-root . gate developer --path <path> --operation modify
python3.11 -m a2a_runtime.cli --project-root . risk list
python3.11 -m a2a_runtime.cli --project-root . report
```

### 会写 workspace 的命令

这些命令必须带 `--yes` 才实际写入；多数支持 `--dry-run` 预览：

```bash
python3.11 -m a2a_runtime.cli --project-root . task create ...
python3.11 -m a2a_runtime.cli --project-root . task use T-2026-001 --yes
python3.11 -m a2a_runtime.cli --project-root . review approve --stage architect --step 1 --reviewer zhangxia --yes
python3.11 -m a2a_runtime.cli --project-root . review approve --stage architect --step 2 --reviewer zhangxia --yes
python3.11 -m a2a_runtime.cli --project-root . review reject --stage architect --reviewer zhangxia --reason "原因" --yes
python3.11 -m a2a_runtime.cli --project-root . blocker request ... --yes
python3.11 -m a2a_runtime.cli --project-root . blocker create --from-request M-T-2026-001-001 --yes
python3.11 -m a2a_runtime.cli --project-root . blocker resolve B-T-2026-001-001 --missing-artifacts-resolved --yes
python3.11 -m a2a_runtime.cli --project-root . risk decide RISK-T-2026-001-001 --decision send_to_architect --reason "原因" --by zhangxia --yes
python3.11 -m a2a_runtime.cli --project-root . finalize --yes
python3.11 -m a2a_runtime.cli --project-root . report --output archive/runtime-report.md --yes
```

## 推荐工作流

1. `task create` 创建任务。
2. `prompt pm` 生成 PM Prompt，交给 Cursor 或人工生成 PM artifacts。
3. `prompt architect` 生成 Architect Prompt，生成 `tech-plan`、`file-change-plan`、`risk-plan`。
4. `review approve --stage architect --step 1` 由用户明确审核方案。
5. `prompt developer --path ... --operation ...` 生成 Developer Prompt。
6. `gate developer --path ... --operation ...` 检查 Developer 是否允许写该路径。
7. Cursor 执行 Developer 工作并生成 Developer artifacts。Runtime 本身不写业务源码。
8. `prompt qa` 生成 QA Prompt，生成 QA artifacts。
9. `review approve --stage final --step 1` / `--step 2` 由用户明确做最终审核并由 Controller 分步推进。
10. `finalize --yes` 写 final-delivery。
11. `report` 或 `report --output archive/runtime-report.md --yes` 查看或导出报告。

## 安全边界

Runtime 不做这些事：

- 不自动修改业务源码。
- 不调用真实 LLM。
- 不自动执行 Cursor Prompt。
- 不 commit。
- 不 push。
- 不创建 MR。
- 不修改 `.ai-agents` 协议结构。
- 不修改 `.cursor`。
- 不绕过 Human Review。
- 不绕过 GateService。
- 不自动接受 P0/P1 风险。

Runtime 可以写这些路径：

- `.ai-agents/workspace/<task-id>/task.md`
- `.ai-agents/workspace/<task-id>/state.md`
- `.ai-agents/workspace/<task-id>/messages/**`
- `.ai-agents/workspace/<task-id>/blockers/**`
- `.ai-agents/workspace/<task-id>/human-reviews/**`
- `.ai-agents/workspace/<task-id>/artifacts/final/**`
- `.ai-agents/workspace/<task-id>/archive/**`
- `.ai-agents/workspace/active-task.md`

## GateService 怎么理解

Developer 写源码前必须满足：

- 当前状态是 `developer_processing`。
- `human_review_status == approved`。
- 当前 Agent 是 `developer`。
- 目标路径在 Architect 的 `file-change-plan.md` 白名单中。
- operation 匹配 `create / modify / delete`。
- forbidden 路径如 `package.json`、lock、CI/CD 默认不允许，除非走人工风险决策。

如果 Gate 不通过：

- 状态或审核问题：`gate_failure`
- 缺少白名单或上游产物：`blocker_request`
- 范围扩大、依赖、CI/CD、多方案选择：`risk_decision_required`

## Blocker 怎么用

专业 Agent 只能创建 blocker request：

```bash
python3.11 -m a2a_runtime.cli --project-root . blocker request \
  --from developer \
  --reason "file-change-plan 缺少 src/services/settings.ts" \
  --resume-to-agent architect \
  --resume-to-status architect_processing \
  --missing-artifact file_change_plan \
  --required-fix "补充 src/services/settings.ts 到 file-change-plan" \
  --yes
```

Controller 再创建 Formal Blocker：

```bash
python3.11 -m a2a_runtime.cli --project-root . blocker create \
  --from-request M-T-2026-001-008 \
  --yes
```

修复后恢复：

```bash
python3.11 -m a2a_runtime.cli --project-root . blocker resolve B-T-2026-001-001 \
  --missing-artifacts-resolved \
  --yes
```

## Risk Decision 怎么用

查看风险：

```bash
python3.11 -m a2a_runtime.cli --project-root . risk list
python3.11 -m a2a_runtime.cli --project-root . risk show RISK-T-2026-001-001
python3.11 -m a2a_runtime.cli --project-root . risk review RISK-T-2026-001-001
```

记录人工决策：

```bash
python3.11 -m a2a_runtime.cli --project-root . risk decide RISK-T-2026-001-001 \
  --decision send_to_architect \
  --reason "需要重新设计权限控制点" \
  --by zhangxia \
  --yes
```

P0/P1 风险不会被 Runtime 自动接受。

## 真实项目试接入建议

1. 先只跑只读命令：`status`、`validate`、`task list`、`report`。
2. 用 `task create --dry-run` 预览写入计划。
3. 确认 project root 正确后再 `task create --yes`。
4. 先走 PM / Architect / Review，不急着让 Developer 写源码。
5. Developer 写源码前必须先跑 `gate developer`。
6. 如果涉及依赖、lock、CI/CD、范围扩大，走 Risk Decision。
7. 每个阶段可以 `report --output archive/runtime-report.md --yes` 留档。
