## 1. 快速理解

```
Runtime（CLI）   →  管流程、文件、门禁、验收
Cursor Agent     →  理解需求、写业务代码
你（人类）        →  审核方案、做风险决策、最终拍板
```

Runtime **不调用 LLM、不写业务源码、不 commit、不 push**。
它只负责生成 Prompt、维护状态、做门禁校验。

## 2. 如何触发 A2A 模式

Cursor 主对话默认按普通问题处理，只有满足下面任一条件才进入 A2A 模式（打 `[A2A]` 头、读 state.md 等）。

### 2.1 触发方式一览


| 方式              | 示例                                                  | 说明                                       |
| --------------- | --------------------------------------------------- | ---------------------------------------- |
| **简写开关**（推荐）    | `a2a 推进 architect`                                  | 消息 trim 后以 `a2a` 或 `A2A` 开头，紧跟空白或英文逗号即触发 |
| 完整关键词           | `走 A2A` / `启动 A2A` / `A2A Task` / `推进 task` / `跑流程` | 消息中包含以上任一词                               |
| `a2a-agent` 关键词 | `a2a-agent 跑完了，帮我看结果`                               | 消息中含 `a2a-agent`                         |
| `[A2A]` 头       | `[A2A] 现在是什么状态？`                                    | 消息本身带 `[A2A]` 格式头                        |
| 操作 workspace 文件 | 要求读写 `task.md` / `state.md` / `artifacts/`** 等      | 显式要求操作 workspace 内文件                     |


### 2.2 不触发的情况

- `a2a是什么`（`a2a` 后直接粘连中文，视为概念问答）
- 普通代码问题、日常对话

### 2.3 触发后 Cursor 会做什么

1. 读 `.cursor/rules/ai-agents-full.mdc` 完整规则
2. 每次回复以 `[A2A]` 头开始（含当前 Agent / Task / Status）
3. 4 步识别当前 Task
4. 按 5 条写代码门禁自检

## 3. 模型选择与切换

有三套独立机制，适用场景不同，互不冲突。

### 3.1 方式一：Cursor Agent 面板切换（日常对话用）

**文件位置**：`.cursor/agents/<role>.md`

已预置 5 个 agent 文件：


| 文件                             | Role   | 默认模型                                |
| ------------------------------ | ------ | ----------------------------------- |
| `.cursor/agents/pm.md`         | 产品经理   | `claude-4.6-sonnet-medium-thinking` |
| `.cursor/agents/architect.md`  | 架构师    | `claude-opus-4-7-thinking-high`     |
| `.cursor/agents/developer.md`  | 高级前端开发 | `gpt-5.5`                           |
| `.cursor/agents/qa.md`         | 测试     | `claude-opus-4-7-thinking-high`     |
| `.cursor/agents/controller.md` | 流程控制器  | `gpt-5.5-mini`                      |


**如何切换**：

- 在 Cursor Agent 面板里找到对应 agent，点击 Model 下拉选择
- 或直接编辑对应 `.md` 文件的 `model:` 字段

```yaml
---
name: architect
model: claude-opus-4-7-thinking-high   # ← 改这里
description: ...
---
```

> 此方式只影响 **Cursor 主对话窗口**的模型，不影响 CLI Runtime。

---

### 3.2 方式二：model-overrides.md 勾选（CLI 跑流程用）

**文件位置**：`.ai-agents/agent-cards/model-overrides.md`

把想用的模型前面的 `[ ]` 改成 `[x]` 即可：

```markdown
## architect

- [x] claude-opus-4-7-thinking-high  -- 默认推荐
- [ ] gpt-5.5
- [ ] claude-4.6-sonnet-medium-thinking
```

**规则**：

- 每个 `## <role>` 下最多勾一个；多勾取第一个并发 warning
- 不勾任何一项 = 使用 runtime 默认推荐
- 清单里没有的模型，直接加一行 `- [x] your-custom-slug`

> 此方式影响 `**a2a-agent prompt <role>` 生成的 prompt** 里的推荐模型提示，不会自动切换 Cursor。

---

### 3.3 方式三：CLI `--model` 一次性覆盖

```bash
python3.11 -m a2a_runtime.cli --project-root . prompt architect --model gpt-5.5
```

只对这次命令生效，不持久化。

---

### 3.4 弹窗触发逻辑（A2A 对话维度）

在 A2A 流程里召唤 sub-agent 前，Cursor 按以下顺序检查，有值就**静默跳过弹窗**：

```
model-overrides.md 有 - [x] 勾选？   → 静默使用，不弹窗
  ↓ 否
.cursor/agents/<role>.md 有 model: ？ → 静默使用，不弹窗
  ↓ 否
两处均无配置                          → 弹 AskQuestion 让你选
```

**推荐做法**：在 `.cursor/agents/<role>.md` 里设好 `model:`，以后跑 A2A 不会再弹窗。

### 3.5 CLI 优先级（`a2a-agent` 维度）

```
CLI --model <slug>              ← 最高（一次性）
  ↓
model-overrides.md - [x]        ← 持久化配置
  ↓
agent-cards/<role>.card.md      ← 备用
  ↓
Runtime 默认推荐                 ← 兜底
```

> ⚠️ P0/P1 高风险任务会强制升档到高推理模型，覆盖以上所有配置，不可关闭。

---

### 3.5 查看当前模型配置

```bash
python3.11 -m a2a_runtime.cli --project-root . model list
python3.11 -m a2a_runtime.cli --project-root . model recommend --agent architect
python3.11 -m a2a_runtime.cli --project-root . model policy
```

## 4. 完整工作流：一步一步走任务

### 第 0 步：确认环境

```bash
python3.11 -m a2a_runtime.cli --project-root . status
python3.11 -m a2a_runtime.cli --project-root . validate
python3.11 -m a2a_runtime.cli --project-root . task list
```

---

### 第 1 步：创建任务

```bash
python3.11 -m a2a_runtime.cli --project-root . task create \
  --type feature \
  --title "新增设置页" \
  --priority P1 \
  --owner zhangxia \
  --yes
```

支持 `--dry-run` 预览写入计划。

优先级可选：`P0` / `P1` / `P2`（P0/P1 会触发强制高推理模型）

---

### 第 2 步：PM 阶段

```bash
python3.11 -m a2a_runtime.cli --project-root . prompt pm
```

Runtime 打印 PM Prompt → 你复制到 Cursor（选 `pm` agent）→ Cursor 生成 PM artifacts：

- `artifacts/pm/requirement.md`
- `artifacts/pm/prd.md`
- `artifacts/pm/task-breakdown.md`

完成后 Cursor 会发 `messages/from-pm-001-handoff.md`。

---

### 第 3 步：Architect 阶段

```bash
python3.11 -m a2a_runtime.cli --project-root . prompt architect
```

Runtime 打印 Architect Prompt → 复制到 Cursor（选 `architect` agent）→ Cursor 生成：

- `artifacts/architect/tech-plan.md`（11 节，含最小可行方案）
- `artifacts/architect/file-change-plan.md`（每条目 7 字段白名单）
- `artifacts/architect/risk-plan.md`

> Architect **严禁写任何源码**，只输出方案文件。

---

### 第 4 步：Human Review（方案审核）

你读完 tech-plan 后，决定 approved / rejected / needs_changes：

**审核通过（两步，不能合并）**：

```bash
# 第 1 步：翻 human_review_status
python3.11 -m a2a_runtime.cli --project-root . review approve \
  --stage architect --step 1 --reviewer zhangxia --yes

# 第 2 步：推 current_status → developer_processing
python3.11 -m a2a_runtime.cli --project-root . review approve \
  --stage architect --step 2 --reviewer zhangxia --yes
```

**审核拒绝**：

```bash
python3.11 -m a2a_runtime.cli --project-root . review reject \
  --stage architect --reviewer zhangxia --reason "缺少权限校验方案" --yes
```

---

### 第 5 步：Developer 阶段

先检查写权限（dry-run）：

```bash
python3.11 -m a2a_runtime.cli --project-root . gate developer \
  --path src/pages/settings/index.tsx \
  --operation modify
```

生成 Developer Prompt：

```bash
python3.11 -m a2a_runtime.cli --project-root . prompt developer \
  --path src/pages/settings/index.tsx \
  --operation modify
```

→ 复制到 Cursor（选 `developer` agent）→ Cursor 写源码

**双门禁缺一不可**：

- `state.current_status == developer_processing` ✓
- `state.human_review_status == approved` ✓

Developer 完成后生成：

- `artifacts/developer/implementation-log.md`
- `artifacts/developer/changed-files.md`

---

### 第 6 步：QA 阶段

```bash
python3.11 -m a2a_runtime.cli --project-root . prompt qa
```

→ 复制到 Cursor（选 `qa` agent）→ Cursor 生成：

- `artifacts/qa/test-report.md`（7 维测试，5 状态枚举）
- `artifacts/qa/acceptance-checklist.md`

> QA **禁止在未实际执行的情况下写 `status: pass`**。

---

### 第 7 步：Final Review（最终审核）

```bash
# 第 1 步
python3.11 -m a2a_runtime.cli --project-root . review approve \
  --stage final --step 1 --reviewer zhangxia --yes

# 第 2 步
python3.11 -m a2a_runtime.cli --project-root . review approve \
  --stage final --step 2 --reviewer zhangxia --yes
```

---

### 第 8 步：Final Delivery

```bash
python3.11 -m a2a_runtime.cli --project-root . finalize --yes
```

门禁全部通过后写 `artifacts/final/final-delivery.md`。

---

### 第 9 步：导出报告

```bash
python3.11 -m a2a_runtime.cli --project-root . report
python3.11 -m a2a_runtime.cli --project-root . report --output archive/runtime-report.md --yes
```

## 5. CLI 命令速查

### 只读命令（安全，不改任何文件）

```bash
# 查看当前任务状态
python3.11 -m a2a_runtime.cli --project-root . status

# 校验 workspace 结构
python3.11 -m a2a_runtime.cli --project-root . validate

# 列出所有任务
python3.11 -m a2a_runtime.cli --project-root . task list

# 查看当前激活任务
python3.11 -m a2a_runtime.cli --project-root . task active

# 生成各 Agent Prompt（只打印，不写文件）
python3.11 -m a2a_runtime.cli --project-root . prompt pm
python3.11 -m a2a_runtime.cli --project-root . prompt architect
python3.11 -m a2a_runtime.cli --project-root . prompt developer --path <路径> --operation modify
python3.11 -m a2a_runtime.cli --project-root . prompt qa
python3.11 -m a2a_runtime.cli --project-root . prompt controller

# Developer Gate 预检
python3.11 -m a2a_runtime.cli --project-root . gate developer --path <路径> --operation modify

# 查看风险
python3.11 -m a2a_runtime.cli --project-root . risk list
python3.11 -m a2a_runtime.cli --project-root . risk show RISK-T-2026-001-001
python3.11 -m a2a_runtime.cli --project-root . risk review RISK-T-2026-001-001

# 模型推荐
python3.11 -m a2a_runtime.cli --project-root . model list
python3.11 -m a2a_runtime.cli --project-root . model recommend --agent architect

# 报告
python3.11 -m a2a_runtime.cli --project-root . report
```

### 写文件命令（需加 `--yes`）

```bash
# 创建任务
python3.11 -m a2a_runtime.cli --project-root . task create \
  --type feature --title "xxx" --priority P1 --owner zhangxia --yes

# 切换激活任务
python3.11 -m a2a_runtime.cli --project-root . task use T-2026-002 --yes

# 审核
python3.11 -m a2a_runtime.cli --project-root . review approve --stage architect --step 1 --reviewer zhangxia --yes
python3.11 -m a2a_runtime.cli --project-root . review approve --stage architect --step 2 --reviewer zhangxia --yes
python3.11 -m a2a_runtime.cli --project-root . review reject --stage architect --reviewer zhangxia --reason "原因" --yes

# Blocker
python3.11 -m a2a_runtime.cli --project-root . blocker request \
  --from developer --reason "缺 file-change-plan 条目" \
  --resume-to-agent architect --resume-to-status architect_processing \
  --missing-artifact file_change_plan --required-fix "补充条目" --yes
python3.11 -m a2a_runtime.cli --project-root . blocker create --from-request M-T-2026-001-008 --yes
python3.11 -m a2a_runtime.cli --project-root . blocker resolve B-T-2026-001-001 --missing-artifacts-resolved --yes

# 风险决策
python3.11 -m a2a_runtime.cli --project-root . risk decide RISK-T-2026-001-001 \
  --decision send_to_architect --reason "原因" --by zhangxia --yes

# 最终交付
python3.11 -m a2a_runtime.cli --project-root . finalize --yes

# 导出报告
python3.11 -m a2a_runtime.cli --project-root . report --output archive/runtime-report.md --yes
```

### 常用参数


| 参数                     | 说明                          |
| ---------------------- | --------------------------- |
| `--project-root .`     | 指定项目根目录（必填，推荐用 `.`）         |
| `--task-id T-2026-001` | 显式指定 task，覆盖 active-task.md |
| `--json`               | 输出 JSON 格式，适合脚本解析           |
| `--dry-run`            | 预览写入计划，不实际写文件               |
| `--yes`                | 真正写文件时必须加                   |
| `--model <slug>`       | 一次性覆盖模型推荐                   |

## 6. Blocker 处理

### 两阶段流程

```
专业 Agent（PM/Architect/Developer/QA）
  → 发现阻塞 → 写 blocker-request message
      ↓
Flow Controller
  → 读 blocker-request → 创建正式 Blocker（B-*.md）→ 改 state 为 blocked
      ↓
修复阻塞后
  → blocker resolve → state 恢复到 resume_to_status
```

### Gate 不通过的两种情况


| 失败类型                            | 上报方式                   | Controller 动作                |
| ------------------------------- | ---------------------- | ---------------------------- |
| 路径不在 file-change-plan 白名单（真实阻塞） | `blocker-request`      | 创建正式 Blocker，改 state=blocked |
| state 阶段错误 / 门禁未过（Agent 误启动）    | `gate-failure-request` | 不创建 Blocker，仅对话提示            |

## 7. 风险决策（Risk Decision）

P0/P1 风险**不会被 Runtime 自动接受**，必须人工介入。

### 可选决策


| decision            | 含义                   |
| ------------------- | -------------------- |
| `accept`            | 接受风险，继续推进            |
| `reject`            | 拒绝方案，退回 Architect 重做 |
| `send_to_architect` | 转交 Architect 给出缓解方案  |
| `defer`             | 延后处理，标记为已知风险         |


```bash
python3.11 -m a2a_runtime.cli --project-root . risk decide RISK-T-2026-001-001 \
  --decision accept \
  --reason "风险已知，已有回滚方案" \
  --by zhangxia \
  --yes
```

## 8. 安全边界

**Runtime 绝对不做的事**：

- 不自动修改业务源码
- 不调用真实 LLM
- 不自动执行 Cursor Prompt
- 不 commit / push / 创建 MR
- 不绕过 Human Review
- 不绕过 GateService 门禁
- 不自动接受 P0/P1 风险
- 不修改 `.ai-agents` 协议结构
- 不修改 `.cursor` 规则文件

**写文件只在 workspace 内**：

```
.ai-agents/workspace/<task-id>/task.md
.ai-agents/workspace/<task-id>/state.md
.ai-agents/workspace/<task-id>/messages/**
.ai-agents/workspace/<task-id>/blockers/**
.ai-agents/workspace/<task-id>/human-reviews/**
.ai-agents/workspace/<task-id>/artifacts/final/**
.ai-agents/workspace/<task-id>/archive/**
.ai-agents/workspace/active-task.md
```

## 附：A2A 状态机流转

```
pm_processing
  → pm_completed
  → architect_processing
  → architect_completed
  → human_review_required   ← 人工审核方案
  → developer_processing    ← 双门禁写代码
  → developer_completed
  → qa_processing
  → qa_completed
  → final_review_required   ← 人工最终审核
  → completed               ← finalize 写 final-delivery
```

任何阶段出现问题 → `blocked`（等 Blocker 处理）→ 恢复到对应阶段
